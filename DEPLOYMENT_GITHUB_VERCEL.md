# Подготовка к GitHub и Vercel

## Важно до публикации

Этот пакет очищен от `.env`, `.venv`, локальной SQLite-базы и загруженных фотографий. Не загружайте секреты и реальные данные практикантов в GitHub.

Vercel поддерживает Flask и автоматически обнаруживает приложение в `app.py`, но файловая система функций в основном доступна только для чтения, а `/tmp` временный. Поэтому текущая локальная SQLite-база и каталог `private_uploads` не подходят для постоянного хранения на Vercel.

До использования с реальными практикантами необходимо подключить постоянную PostgreSQL-базу и приватное объектное хранилище фотографий, а затем адаптировать код для записи/чтения фотографий через это хранилище. Не разворачивайте текущую версию как рабочую систему для персональных данных до этой доработки.

## GitHub
1. Создайте отдельный новый репозиторий, например `practice-attendance`. Не используйте репозиторий DrivePro.
2. Загрузите содержимое этой папки в корень нового репозитория.
3. Убедитесь, что в репозитории нет `.env`, `.venv`, `attendance.db` и фотографий из `private_uploads`.

## Vercel
После настройки постоянной базы данных и приватного хранилища подключите отдельный проект через Import Git Repository. Vercel умеет автоматически обнаруживать Flask-приложение. Настройки подключения и секреты добавляйте в Project Settings → Environment Variables, не в Git.


**Структура проекта:** все файлы проекта расположены в корне репозитория, без вложенных папок.


## Обновление дизайна и полей практиканта

- Все файлы по-прежнему находятся в корне проекта; вложенные папки не нужны.
- В форме регистрации учебное заведение выбирается из выпадающего списка, а номер пропуска вводится только цифрами. Для уже созданных аккаунтов доступно действие «Изменить данные».
- В административной панели есть папка фотографий за выбранную дату; карточка показывает фотографию цифрового пропуска, ФИО практиканта, номер пропуска, группу и время.
- `app.py` добавляет новые поля `educational_institution` и `pass_number` к существующей таблице пользователей. Перед развёртыванием убедитесь, что у базы есть резервная копия.
- Не удаляйте старые файлы по одному перед загрузкой: загрузите обновлённые файлы в корень репозитория и сделайте один commit, чтобы избежать серии неудачных промежуточных деплоев.
- Важно: SQLite и `/tmp` на Vercel не обеспечивают постоянное хранение базы и фотографий. До реального использования подключите PostgreSQL и приватное объектное хранилище.


## Карта MapTiler

- Создайте API-ключ MapTiler и ограничьте его разрешёнными HTTP-источниками для используемых доменов сайта. Не добавляйте сам ключ в GitHub и не отправляйте его в чат.
- В Vercel откройте Project → Settings → Environment Variables и добавьте `MAPTILER_API_KEY` со значением ключа. Отметьте Production (и Preview, если тестируете preview-деплои).
- Сохраните переменную и выполните Redeploy последнего Production deployment.
- После развёртывания войдите в админ-панель и откройте «Точка практики и карта». Проверьте, что карта показывает улицы и здания, можно выбирать точку кликом и перетаскиванием маркера, а круг показывает заданный радиус.
- Если тайлы не загружаются, проверьте ограничения Allowed HTTP Origins у ключа и консоль браузера.
